**Готовые инструменты и репозитории (особенно GitHub) для задачи отбора кадров по жёстким теням.**

Задача хорошо ложится на классические методы компьютерного зрения + пакетную обработку + запись метаданных. Полноценных «готовых фреймворков именно под промышленные строительные фото с дрона» почти нет, но есть сильные строительные блоки, из которых можно быстро собрать свой локальный пайплайн (CLI или простой веб-сервер).

**Простые OpenCV-решения (нет отдельного большого репо, но легко воспроизводятся):**
- Пороговая обработка в HSV/Lab + проверка резкости границ (градиент).
- Много примеров на StackOverflow и Medium по «shadow detection OpenCV Python».

**Контраст и метрики качества:**
- OpenCV (`cv2.Laplacian`, градиенты Sobel/Scharr, `cv2.meanStdDev`).
- scikit-image (`skimage.exposure.is_low_contrast`, `measure`, локальные гистограммы, entropy).
- Нет «готового» репозитория именно под hard-shadow contrast, но комбинация Laplacian variance + процент сильных градиентов + доля тёмных регионов работает отлично.

**Метаданные (ACDSee):**
- **exiftool** — абсолютный стандарт. Поддерживает `XMP-xmp:Rating`, `XMP-acdsee:Rating`, Keywords, Labels, Categories, произвольные XMP-поля. ACDSee читает стандартный Rating и IPTC/XMP Keywords; для полного совместимости пишите и в `XMP-acdsee`.
- Python-обёртки: `piexif` (только EXIF, слабо), `pyexiv2`, лучше всего вызывать exiftool через `subprocess`.
- Есть конфиг `acdsee.config` в репозитории exiftool.

**Пакетная обработка + локальный сервер:**
- OpenCV + multiprocessing / joblib / concurrent.futures.
- Для GUI/веб: Streamlit, Gradio, FastAPI + HTMX/Vue (очень быстро сделать просмотр + ручную корректировку).
- Полностью локально, без облака и GPU (классика) или с опциональным GPU (лёгкие DL).

### 1. Методы и метрики измерения контраста / hard shadows

**Общие метрики контраста:**
- **Michelson contrast** = (Imax − Imin)/(Imax + Imin) — глобальный, плохо ловит локальные тени.
- **RMS contrast** = стандартное отклонение интенсивности (после нормализации).
- **Local contrast** — std в скользящем окне, или variance of Laplacian (очень популярна как proxy «резкости/контрастности»).
- **Entropy-based** — информационная энтропия гистограммы (высокие значения = больше деталей/контраста).
- **Gradient-based** — среднее/процентили магнитуды градиента (Sobel, Scharr, Laplacian).

**Лучше всего для жёстких («ползущих») теней:**
- Высокий процент пикселей с большим градиентом на границах тёмных регионов (жёсткая тень = резкий перепад).
- Доля площади тёмных регионов + их «резкость границ».
- Комбинация: 
  1. Конвертация в Lab/YCbCr/HSV.
  2. Порог по L/V (тёмные области).
  3. Маска границ (Canny/Sobel) внутри/на границе этих областей.
  4. Метрика = площадь тени × средняя сила градиента на границе + глобальный RMS/Laplacian.

Классические подходы (Finlayson chromaticity, LAB-пороги, mean-shift) работают лучше чистого глобального контраста именно на hard shadows.

Готовых open-source решений под «hard shadow detection на RGB» много в awesome-листах выше. На обычных строительных фото (бетон, металл, однородные поверхности) классика часто достаточна и быстрее.

### 2. Инструменты и библиотеки

**Рекомендуемый стек (быстрый, CPU-only):**
- **OpenCV** — основной (чтение, цветовые пространства, градиенты, пороги, морфология).
- **NumPy / SciPy** — быстрые метрики.
- **scikit-image** — дополнительные меры контраста/энтропии (если нужно).
- **Pillow** — только если нужны простые операции или сохранение.
- **exiftool** (через subprocess) — метаданные.
- **multiprocessing** или **joblib** — пакетная обработка.
- Опционально: **torch** + лёгкая модель (FSDNet и т.п.), если классика даёт много ошибок.

Сравнение:
- OpenCV — самый быстрый и достаточный для прототипа.
- scikit-image — удобнее для метрик, чуть медленнее.
- Специализированные shadow-репозитории — берите код детекции и встраивайте.
- Pretrained DL — только если классика не справляется (сложное освещение, мягкие→жёсткие переходы). На обычном ПК без GPU лёгкие модели работают, но медленнее.

### 3. Работа с метаданными для ACDSee

Лучшие поля (в порядке предпочтения):
1. **Rating** (0–5) — `XMP-xmp:Rating` + `XMP-acdsee:Rating`.
2. **Keywords** / Labels — `IPTC:Keywords` или `XMP-dc:Subject` + `XMP-acdsee:Keywords`.
3. **Categories** / Labels (цветные метки ACDSee).
4. Пользовательские XMP-поля (если нужно хранить числовую метрику контраста).

Пример команды:
```bash
exiftool -XMP-xmp:Rating=5 -XMP-acdsee:Rating=5 -Keywords+="good_no_hard_shadow" -overwrite_original file.jpg
```

ACDSee хорошо видит Rating и Keywords, если они записаны правильно. Тестируйте на своей версии ACDSee (бывают нюансы с namespace).

Библиотеки:
- **exiftool** — лучший выбор (полнота, скорость, надёжность).
- pyexiv2 / piexif — можно, но exiftool надёжнее для XMP-acdsee.

### 4. Архитектура решения (3 варианта)

**1. Простой CLI-скрипт (рекомендую начать с него)**  
Пайплайн: папка → загрузка → расчёт метрик (контраст + shadow score) → классификация по порогам → запись Rating/Keywords через exiftool → лог/CSV.  
Библиотеки: OpenCV + NumPy + subprocess(exiftool) + argparse + tqdm.  
Объём: 150–300 строк.  
Пороги: конфиг-файл или аргументы CLI (`--shadow_threshold 0.15 --contrast_threshold 40`).

**2. CLI + простой GUI (Streamlit / Gradio)**  
Тот же пайплайн + веб-страница: загрузка папки, превью с масками теней, слайдеры порогов, ручная корректировка рейтинга, пакетная запись.  
Сложность: +100–200 строк. Идеально для калибровки.

**3. Продвинутый (FastAPI + фронт + возможность ручной правки)**  
Бэкенд обрабатывает папку асинхронно, сохраняет результаты в SQLite/JSON, фронт показывает галерею с фильтрами, позволяет менять метки и перезаписывать метаданные.  
Можно добавить «обучение» порогов на размеченном наборе.  
Сложность: средняя (несколько файлов).

### 5. Практические рекомендации

- **Промышленные фото**: бетон/металл/земля дают большие однородные области → глобальный контраст часто врёт. Обязательно используйте локальные метрики + долю площади теней с резкими границами. Переменное освещение (утро/день) требует адаптивных порогов или нормализации.
- **Калибровка**: возьмите 50–100 кадров, разметьте вручную (хороший/плохой/пограничный), посчитайте распределение ваших метрик, выберите пороги по ROC или просто вручную. Сохраните калибровочный набор.
- **Подводные камни**:
  - Разный баланс белого и время суток → работайте в Lab или нормализуйте.
  - JPEG-сжатие добавляет артефакты на границах → лёгкое размытие перед градиентом или морфология.
  - Мягкие тени vs жёсткие — классика иногда путает; можно добавить проверку «резкости границы».
  - Большие файлы с дрона → уменьшайте для анализа (например, до 1024 px по длинной стороне), оригиналы не трогайте.

### Конкретная рекомендация для быстрого рабочего прототипа

**Стек:**
- Python + OpenCV + NumPy
- Простая метрика: Laplacian variance + доля тёмных регионов (Lab L-канал) с сильным градиентом на границе
- Классификация по двум-трём настраиваемым порогам
- Запись через exiftool (Rating + Keywords)
- Обёртка: CLI → потом Streamlit для калибровки

Начните с классики из репозиториев LAB и mean-shift + собственных градиентных метрик. Это работает на обычном ПК без GPU, быстро и достаточно точно для большинства строительных площадок. Если качество не устроит — подключите лёгкую модель из Unveiling-Deep-Shadows (FSDNet и аналоги).

Могу помочь набросать конкретный код пайплайна или разобрать любой из указанных репозиториев подробнее.
