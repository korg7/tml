# Спецификация реализации: Автоотбраковка кадров с жёсткими тенями

## 1. Суть задачи

Пакетный анализ фотографий промышленной стройплощадки (съёмка с дрона / стационарной камеры).
Автоматическая классификация: **good / review / bad** по наличию жёстких теней.
Запись разметки в метаданные файлов для фильтрации в ACDSee.

Жёсткая тень мешает стабилизации: алгоритм цепляется за резкие границы свет/тень.

## 3. Метод детекции теней (ядро алгоритма)

### Основной подход: комбинированный классический

Синтез лучших идей из всех отчётов:

1. **Теневая маска** — метод Silva 2017 (CIELCh + Specthem ratio) + адаптивный порог по L-каналу LAB.
   - Источник: [Shadow-Detection-Algorithm-for-Aerial-and-Satellite-Images](https://github.com/ThomasWangWeiHong/Shadow-Detection-Algorithm-for-Aerial-and-Satellite-Images)
   - Релевантен: написан именно для аэрофотосъёмки, ~93% точность, near real-time, CPU.

2. **Резкость границы тени** — средний градиент (Scharr) вдоль контура маски.
   - Жёсткая тень → высокий градиент, мягкая/облако → низкий.
   - Напрямую моделирует проблему стабилизации.

3. **Бимодальность гистограммы** — межклассовая дисперсия Отсу как быстрый глобальный признак «свет/тень».

4. **Локальный контраст** — RMS в скользящих окнах (32–64 px), P95 по окнам.

5. **Цветовая согласованность** — в тени L падает, цветность (a, b) меняется слабо; если меняется сильно → это объект, не тень.

### Почему не DL на старте

- Исследовательские репо (BDRAR, MTMT) — старые зависимости, нет удобного inference, обучены на бытовых фото.
- Классика + калибровка на 100–300 своих кадрах даёт контролируемый и интерпретируемый результат.
- 5–20 кадров/сек на CPU без GPU.

## 4. Набор признаков (features)

### 4.1. Предобработка

```
resize max_side = 1280 px
GaussianBlur σ≈1 (убирает JPEG-артефакты 8×8)
convert BGR → LAB
L = яркостный канал (float32, 0..1)
Нормализация: L_norm = (L - p1) / (p99 - p1 + eps)
```

### 4.2. Глобальные признаки

| Признак | Формула / суть |
|---------|----------------|
| `rms_contrast` | std(L_norm) |
| `michelson_pct` | (p99 − p1) / (p99 + p1 + eps) |
| `dynamic_range` | p95 − p5 |
| `histogram_entropy` | энтропия гистограммы L (256 bin) |
| `bimodality` | межклассовая дисперсия Отсу / дисперсия между модами |
| `clipped_highlight_ratio` | доля пикселей L > 0.98 |

### 4.3. Локальные признаки

| Признак | Формула / суть |
|---------|----------------|
| `local_contrast_p95` | P95 от std(L) в скользящих окнах 48×48 |
| `local_contrast_p50` | P50 (медиана) — для контекста |

### 4.4. Градиентные признаки

| Признак | Формула / суть |
|---------|----------------|
| `sobel_p95` | P95 магнитуды Sobel(L) |
| `edge_pixel_ratio` | доля Canny-edge пикселей |

### 4.5. Теневые признаки (ключевые)

| Признак | Формула / суть |
|---------|----------------|
| `shadow_area_ratio` | доля пикселей в теневой маске |
| `boundary_gradient_mean` | средний Scharr-градиент на границе маски |
| `boundary_brightness_drop` | средний перепад L поперёк границы (светлая−тёмная сторона) |
| `boundary_length_norm` | суммарная длина границ маски / диагональ изображения |
| `chroma_diff_at_boundary` | среднее |Δa| + |Δb| на границе (мало для тени, много для объекта) |

### 4.6. Итоговый shadow_score

```
shadow_score = w1 * boundary_brightness_drop_norm
             + w2 * boundary_gradient_norm
             + w3 * shadow_area_ratio_norm
             + w4 * boundary_length_norm
             + w5 * (1 - chroma_diff_norm)   # инвертирован: мало цвета = больше тень
```

Начальные веса: `[0.30, 0.25, 0.20, 0.10, 0.15]`.
Калибруются на размеченном наборе (логистическая регрессия / подбор по ROC).

## 5. Классификация

### Режим 1: Правила (старт)

```yaml
classification:
  good_shadow_score_max: 0.25
  good_local_contrast_max: 0.22
  bad_shadow_score_min: 0.55
  bad_local_contrast_min: 0.38
```

```
if shadow_score < good_max AND local_contrast_p95 < good_lc_max → GOOD
elif shadow_score > bad_min OR local_contrast_p95 > bad_lc_min → BAD
else → REVIEW
```

### Режим 2: ML (после калибровки)

LogisticRegression / малое дерево на 7–8 признаках.
Обучается на 100–300 размеченных кадрах за секунды, остаётся интерпретируемой.

```
P(bad) > 0.70 → BAD
P(good) > 0.70 → GOOD
else → REVIEW
```

Приоритет: **high recall для bad** (лучше перепроверить, чем пропустить тень в стабилизацию).

## 6. Метаданные для ACDSee

### Схема записи

| Класс | Rating | Label | Keywords |
|-------|--------|-------|----------|
| GOOD | 5 | Green | `QC_GOOD`, `NO_HARD_SHADOW` |
| REVIEW | 3 | Yellow | `QC_REVIEW`, `POSSIBLE_SHADOW` |
| BAD | 1 | Red | `QC_BAD`, `HARD_SHADOW` |

### Поля (пишем оба namespace для совместимости)

```bash
exiftool -overwrite_original \
  -XMP-xmp:Rating=<N> -XMP-acdsee:Rating=<N> \
  -XMP-xmp:Label="<Color>" \
  -XMP-dc:Subject+="<keyword>" \
  -IPTC:Keywords+="<keyword>" \
  file.jpg
```

### Критичные нюансы

- **JPEG**: ACDSee НЕ читает XMP-sidecar для JPEG → встраиваем в сам файл.
- **Categories**: ACDSee игнорирует записанные сторонним софтом → НЕ используем.
- После записи → перекаталогизировать (Catalog) в ACDSee.
- Писать атомарно, сначала `--dry-run` (только CSV, без модификации файлов).
- Batch-режим ExifTool (`-stay_open`) для скорости.

## 7. Архитектура (поэтапная)

### Этап 1 — CLI-скрипт (основная разработка)

```
shadow-qc/
├── config.yaml              # пороги, пути, параметры
├── requirements.txt
├── src/
│   ├── __init__.py
│   ├── cli.py               # argparse, точки входа
│   ├── pipeline.py          # оркестрация: обход → анализ → классификация → запись
│   ├── features.py          # извлечение всех признаков
│   ├── shadow_mask.py       # построение теневой маски (Silva + LAB)
│   ├── classify.py          # правила / ML-классификатор
│   ├── metadata.py          # ExifTool batch-запись
│   └── utils.py             # IO, resize, логирование
├── scripts/
│   ├── calibrate.py         # калибровка порогов на размеченном наборе
│   └── visualize_debug.py   # overlay масок для отладки
├── data/
│   ├── labeled.csv          # ручная разметка (filename, label)
│   └── predictions.csv      # результат работы
└── debug/
    ├── masks/               # теневые маски
    └── overlays/            # визуализация поверх фото
```

**Пайплайн:**
```
Папка → поиск JPG/PNG/TIF
  → для каждого файла (параллельно):
      resize 1280 → blur → LAB → признаки → shadow_score → класс
  → CSV с метриками
  → [если не --dry-run] ExifTool batch → Rating/Label/Keywords
  → итоговый отчёт в консоль (good/review/bad counts)
```

**Объём:** ~500–800 строк.

### Этап 2 — Streamlit-панель калибровки

- Загрузка кэша метрик (features.parquet).
- Слайдеры порогов → мгновенный пересчёт классов.
- Галерея превью с overlay теневых масок.
- ROC / confusion matrix по размеченному набору.
- Кнопка «Применить метаданные».

**Объём:** +300–500 строк.

### Этап 3 (опционально) — DL для пограничных кадров

- Если классика даёт >15% ошибок на review-кадрах.
- Подключить MTMT или BDRAR (порт на PyTorch 1.7) только для кадров с классом REVIEW.
- Или: ONNX Runtime + FSDNet (лёгкая real-time модель).

  workers: 4               # 0 = auto (cpu_count)

## 9. Практические решения для промышленных фото

| Проблема | Решение |
|----------|---------|
| Бетон (однородный, светлый) | Опираемся на локальные метрики + маску, не на глобальный контраст |
| Металл (блики) | Отличаем: блик = насыщение в светах (L > 0.98), тень = тёмный кластер |
| Тёмные объекты (техника, битум) | Проверяем цветовой сдвиг: тень не меняет цветность, объект — меняет |
| Переменное освещение | Нормализация по перцентилям, не абсолютные пороги |
| JPEG-артефакты | GaussianBlur σ≈1 перед градиентами |
| Разный баланс белого | Все метрики по L-каналу; хроматика — только как отношения |
| Автоэкспозиция | CLAHE / нормализация для относительных метрик; градиент границы — по исходнику |
| Облачная кромка (псевдотень) | Метрика резкости границы отделит: мягкий переход ≠ жёсткая тень |
| Стационарная камера | Медианный кадр серии как reference «без теней» (бонусный признак) |
| Время из EXIF | Дешёвый предфильтр: низкое солнце → почти гарантированно жёсткие тени |

## 10. Калибровка порогов

1. Разметить вручную **150–300 кадров** (good / review / bad), включая утро/день/вечер, облачно/солнечно.
2. Прогнать `features.py` → `features.parquet`.
3. Построить распределения признаков по классам.
4. Пороги → точка пересечения распределений или ROC.
5. Если одиночные пороги дают >10% ошибок → LogisticRegression на 7–8 признаках.
6. Класс REVIEW делать широким: дешевле вручную просмотреть 10%, чем потерять хорошие кадры.
